An open app is not a viewer.

A session counts as a concurrent viewer only while it is playing, foregrounded and heartbeat-fresh. ClickLiv computes that rule over SonyLIV streaming telemetry entirely inside ClickHouse, and proves the answer against independent paths that share no code.

The same intervals also feed minute_deltas, maxIntersections and a Python reference that reads the CSV directly. Twelve checks diff all four.

Land the events, aggregate nothing on the way in

Every telemetry row goes into a partitioned MergeTree exactly as it arrived, so any later decision about what counts as watching can be revisited without a reload.

Sessionize into active intervals

A window function turns ordered events into intervals of genuine playback. Intervals close on pause, background, error, session end and on any heartbeat gap past the threshold, and they reopen on play, resume and foreground while playing. Closing never waits for a matching marker, because the markers do not balance in this data.

Collapse to one row per session and minute

A session that plays in several bursts inside one minute is still one viewer in that minute. Deduplicating to a single active flag per session and minute buys the property the whole serving layer rests on: per-minute concurrency is additive across dimensions, so summing slice counts gives the total.

Sum signed deltas as a second, differently built path

The same intervals become plus one and minus one events on merged runs, summed into a SummingMergeTree and read back as a windowed cumulative sum. It exists to disagree with the rollup, and it never does.

Serve one parameterized view, behind a budgeted role

Curated marts views answer any combination of dimension filter, time range and grain. Filtering happens before aggregation and aggregation is always to minute, so the order of operations holds whatever is asked. Consumers hold a read-only role scoped to marts and nothing underneath, with a query budget the server enforces rather than a prompt.

Cross-check against an oracle that shares no code

maxIntersections computes the same overlap arithmetically with no rollup involved, and a Python reference reads the source CSV and owes ClickHouse nothing. The pipeline also rebuilds byte identically, runs on a held out single day, and reproduces the same hashes in chDB with no server at all.

What is measured, and what is not

Concurrency has two defensible readings and nobody upstream published which one counts

Occupancy means any active playback inside the minute. Instantaneous means overlap at a point in time. They differ at every slice, so both are computed and both are published. Occupancy leads because the problem statement's own worked example reads that way.

Paused playback is excluded on purpose

The question is who is watching, not who has the app open. That is a stated choice rather than a discovered fact, and it is one predicate to flip if the definition differs.

Liveness thresholds come from the measured heartbeat cadence, not the data dictionary

The documented cadence and the observed one disagree, so every threshold derives from the measurement. The two remaining guesses are swept across a grid rather than argued for, and the sweep ships with the answer.

Average concurrency is reported against two denominators

There is no single defensible denominator and the choice moves the answer, so both are labelled everywhere they appear instead of one being quietly picked. The average above divides by the minutes in which any session was open.

Dimension values are published exactly as stored

The source spells some language codes more than one way and those spellings stay distinct here. Nothing is silently merged, because merging two real values would inflate a slice without anyone noticing.

Serving latency moves between runs

The stable claim is the target, p99 under 100 ms, self-imposed because no upstream SLA was ever published. Every figure is query_duration_ms read back by query id, never client wall clock.
