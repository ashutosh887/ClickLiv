The advantage is flat in the number of filters because marts.dimension_value
holds the distinct value of each dimension, so the case-fold fallback in
sql/06_marts.sql resolves against that small table instead of rescanning the
fact table once per predicate. dimension_value carries 225 rows and each resolved
filter reads it twice, so eight filters cost 2,925 rows more than none rather
than another pass over the fact table each.

Before that table existed the same eight-filter query read 871,362 rows, which is
exactly nine passes over the 96,818 row serving table, and the advantage decayed
toward 1x. That measurement is still recoverable from this service's query log:
