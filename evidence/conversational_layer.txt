-- what failed, reproduced verbatim before any change

asked "What has been the most busiest time?" then "As per our records
on the Clickhouse?", the model reached past the guardrailed tools for
the raw SQL escape hatch and emitted:

  SELECT bucket_minute, peak_concurrency
  FROM marts.v_concurrency(
    country='ALL', platform='ALL', video_type='ALL', content_id=0,
    minute_from=toUInt32(toUnixTimestamp(now() - INTERVAL 30 DAY) / 60),
    minute_to=toUInt32(toUnixTimestamp(now()) / 60),
    grain_minutes=1)
  ORDER BY peak_concurrency DESC LIMIT 1;

run against Cloud that returned 0 rows, and the model then asked the
user which filter values were valid. The empty string was the only
accepted "no filter" sentinel, so 'ALL' matched no row; country only
ever holds 'india'.

-- root cause underneath that, found while proving the fix

the marts MCP server bound 127.0.0.1:8765. On Linux the LibreChat
container reaches the host through host.docker.internal, which is the
docker bridge address, not loopback. So on EC2 clickliv-marts attached
ZERO tools while its serverInstructions were still injected, and every
answer came from the escape hatch wearing the guardrailed surface's
name. Fixed by binding every interface, MCP_HOST narrows it again.
Contained by the security group: clickliv-demo-sg has no 8765 rule and
an off-box curl to 15.252.63.157:8765 times out (exit 28).

  ss before   LISTEN 0 5   127.0.0.1:8765
  ss after    LISTEN 0 5     0.0.0.0:8765

-- case folding, and the collision it nearly caused

"LIVE" and "VOD" used to match nothing and answered a confident 0.
Folding case unconditionally was worse: audio_language holds both 'hin'
and 'HIN' as distinct slices, subtitle_language the same, so a blanket
fold turned the 1,614 headline into 1,899. Final rule is exact match
wins, case fold only when nothing matches exactly.
